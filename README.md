# Pi + Obsidian: персональный учебный харнесс

Проектная конфигурация [Pi](https://github.com/earendil-works/pi) для занятий с заметками в Obsidian. Репетитор выясняет, что ученик уже понимает, строит маршрут по предпосылкам, задаёт проверочные вопросы и продолжает занятие с учётом прошлых ответов. Ответы и объяснения записываются в обычный Markdown; интерактивные иллюстрации можно открыть прямо в Obsidian.

## Состав

- `.pi/skills/` — репетитор, диагностика, профиль ученика, визуализация и проверка понимания.
- `.pi/extensions/` — учебное состояние, квизы, журнал Markdown, источники и инструменты для SVG/HTML.
- `.pi/agents/` — вспомогательные агенты для исследования, схем и проверки занятий.
- `.obsidian/snippets/` — оформление учебного журнала и широкой заметки.
- `.pi/tests/` — тесты расширений, не содержащие реальные учебные сессии.

## Быстрый старт

1. Установите Pi с пакетом `@earendil-works/pi-coding-agent` и Obsidian. Откройте **новое хранилище Obsidian** в каталоге клонированного репозитория.
2. В Obsidian включите CSS snippets `md-log-callouts` и при желании `wide-note`. Для интерактивных блоков `artifact` установите сторонний [Artifact Embed](https://community.obsidian.md/plugins/artifact-embed) через каталог плагинов Obsidian.
3. Запустите `pi` из корня репозитория. Создайте заметку в этом хранилище и подключите её командой `/md-log /абсолютный/путь/к/заметке.md`.
4. Вызовите `/learn-profile`, чтобы заполнить свой профиль, затем `/teach` или `/probe` для занятия и диагностики. Для отдельной картинки доступна команда `/visual`.

Pi сохраняет личный профиль и ход обучения в `.alvar/`, активный путь к заметке — в `.pi/mdlog.json`, а созданные иллюстрации — в `visuals/`. Эти каталоги и файлы не входят в Git. Для смены заметки снова вызовите `/md-log`.

Тесты расширений: `sh .pi/tests/run.sh` (нужны Pi и Bun). Они проверены с установленным у автора пакетом Pi; при изменении API расширений может понадобиться адаптация.

## Учебный запуск без лишних ресурсов

Запускайте из корня хранилища:

```sh
./pi-learn
# Продолжить существующую сессию:
./pi-learn --session <session-id>
# Проверить состав без запуска модели:
./pi-learn --print-profile
```

При установке скопируйте также `pi-learn`, `.pi/learning-profile.mjs` и `.pi/learning-launcher.mjs`; при необходимости выполните `chmod +x pi-learn`. Нужны Node и установленная команда `pi`.

Launcher отключает автообнаружение расширений, навыков и шаблонов промптов. Явно загружаются пять учебных расширений и пять проектных навыков. Из текущего каталога Pi (`PI_CODING_AGENT_DIR` или `~/.pi/agent`) подключаются установленные `pdf-reader`, `web-search`, `web-fetch`, `ask-user-question`, `bash-guard` и три служебных расширения Orca. Браузер, субагенты и посторонние навыки автоматически не подключаются. `--print-profile` показывает отсутствующие необязательные компоненты. Собственные дополнительные защитные расширения добавьте в список `learning-profile.mjs` перед использованием этого запуска.

Глобальные настройки, авторизация, модель и история сессий сохраняются. Файлы AGENTS.md/CLAUDE.md продолжают учитываться. Обычная команда `pi` сохраняет стандартное автоподключение; учебный набор действует при запуске `pi-learn`.

Репетитор автоматически получает основные правила, протокол квизов и визуализаций, указатель техник, краткое состояние и профиль активного ученика. Полные карточки техник и дополнительные источники читаются по необходимости. `learning-response` принимает необязательную `assessment`, а оба инструмента оценки — `resolveSupport={basis,nextStep}`. Регистрация ответа, оценка и завершение локальной помощи выполняются одной транзакцией с возвратом свежего контекста. Ошибка откатывает весь составной вызов; повтор того же вызова не дублирует свидетельства. Объединение не оценивает ответ автоматически и не подтверждает освоение за модель.

Это сокращает необходимые служебные обращения. Конкретное ускорение зависит от модели, источников и задания; ограничения на длину объяснений не вводятся.

## План, диагностика и продолжение

Харнесс хранит отдельно:

- договор занятия (`survey`, `teach`, `review`), формат вопросов и точку возврата после помощи;
- содержательный план: главную идею, граф зависимостей с объяснениями, маршрут занятий, источники и межтемные связи;
- реальные ответы, помощь, самостоятельное подтверждение, новые противоречия и сроки повторения;
- подготовленные визуалы и подтверждение записи их вставок в конспект.

`learning-plan` сохраняет версии плана, `learning-map` строит HTML-карту с масштабированием, `learning-inspect` восстанавливает подробности. Старые Markdown-планы доступны как указатели для явного восстановления: их оценки не превращаются автоматически в освоение. `topicId` и явные `aliases` связывают переименования; новая цель не стирает историю знаний. Изменение структуры существующего плана требует `expectedVersion`, удаление областей — `replace` с причиной.

В обзорной диагностике слабая предпосылка не скрывает зависимую ветвь. Можно проверить доступное свойство или сохранить ограничение проверки. Два правильных выбора не отменяют согласованные три варианта. «Не знаю» и просьба объяснить обрабатываются отдельно.

Учебные техники выбираются через `learning-technique` или каталог, без квоты приёмов. Объяснение оценивается по содержательным переходам и реакции ученика; ограничений на число слов нет. HTML — основной формат, явная просьба о Mermaid поддерживается.

Проверено на Pi **0.87.1**, Bun **1.3.14** и Node **26.5.0**. Подробности сценариев и ограничений: [.pi/tests/README.md](.pi/tests/README.md). После обновления файлов перезапустите Pi, чтобы загрузить новые расширения.

## Приватность

Репозиторий содержит только повторно используемый код, инструкции и CSS. В нём нет PDF, конспектов, профилей учеников, базы занятий, истории Obsidian, личных путей и результатов диагностики. `.gitignore` по умолчанию исключает новые заметки и состояние хранилища. Перед публикацией собственных изменений проверяйте `git status` и `git diff --cached`.

Методика вдохновлена материалом Eero Alvar [How I Use AI to Learn Things](https://youtu.be/kzcI5F4tGiU); сведения об авторах заимствованных навыков сохранены в их metadata. Плагин Artifact Embed устанавливается отдельно и не входит в этот репозиторий.
